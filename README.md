プロジェクトの背景と社会的意義
サボテン科（Cactaceae）は、気候変動や人間活動の活発化による自生地の喪失に直面しており、世界で最も絶滅のリスクが高い生物群の一つです。
現在、サボテン科のほぼ全種がワシントン条約（CITES）附属書II類で保護されており、特に危機に瀕している種は附属書I類に指定されています。

植物園や研究者による国際的な保護活動（IUCN CSSG等）が推進される中、園芸市場も大きな過渡期を迎えています。
原種を単なる「希少なコレクション」として消費するのではなく、「保護すべき絶滅危惧種」として扱う倫理的な取引が求められています。

しかし、実際の海外ECサイト（種子・苗の頒布サイト）では、独自の表記ゆれや古い学名（シノニム）での販売が横行しており、
「どの保護対象種が、どこで流通しているか」を網羅的・正確に把握することは極めて困難でした。

・システムによる解決が必要だった複雑な課題例
サボテンは旧来の形態学的分類からAPG分類法の移行により、分類学上の見解が二転三転しやすく、ECサイトごとに異なる名前で流通しています。

例としてCITEs附属書I（最高レベルの保護対象）に指定されている希少種「Pachycereus militaris」が、
旧分類属である「Backebergia militaris」の名前で販売されています。

さらに複雑な階層・記号表記: 「Pediocactus bradyi」などの種において、属名と識別語（亜種名など）が離れて記載されたり、
複雑なラテン語名が混ざった分類上の記号が混在したりすることで、通常の単純な検索システムでは保護種と認識できません。

本システムは、このような従来のシステムでは別物として見逃されやすい複雑な学名のゆれを独自のアルゴリズムで自動名寄せし、
世界中のECサイトから保護種の流通状況を横断的に監視・検索できるデータベースです。

[外部データソース]
  ├─ ワシントン条約(CITES) / IUCNレッドリスト (CSV)
  ├─ World Flora Online (WFO) Plant List (Darwin Core Archive / CC0)
  └─ 海外ECサイト (HTML, JSON API, PDF, Excel)
         ↓ (Node.js スクリプトによる自動収集・照合)
[ローカルデータベース]
  └─ SQLite (マスターデータ・商品情報・照合結果を格納)
         ↓ (静的ファイルとしてエクスポート)
[フロントエンド表示]
  └─ 静的JSON + HTML/CSS/Vanilla JS (サーバーレス構成)

優先順位付き・多段階の学名照合アルゴリズム単なる文字列の一致ではなく、「拾い漏れを防ぐ（inclusive）」設計と「誤検出を防ぐ（安全側に倒す）」設計を両立させるため、
以下の優先順位で多段階の判定を行っています。  
シノニム（異名）は、CITESのシノニム欄に加えて、世界の植物分類の標準リストであるWorld Flora Online (WFO) Plant Listの
サボテン科学名索引から構築しています。CITESが採用する学名とWFOの現行学名は一致しないことがあるため
（例：CITESの「Turbinicarpus mandragora」はWFOでは「Rapicactus mandragora」が現行名）、
入力された学名が異名側に回っている場合も正名まで辿ったうえで、その正名が束ねる別名を全て収集しています。
これにより、属の分割・改称を経た古い流通名（Gymnocactus、Backebergia等）でも同一の保護種として判定できます。
なお、亜種・変種は識別語まで含めた形で保持しています。親種の二名式に丸めてしまうと、
保護種の旧亜種名が非保護の普通種と同一視され、誤検出につながるためです。

・ステップ1〜2: 属＋種小名の完全一致、およびシノニム（異名）の完全一致による厳密な判定する。
・ステップ2b（独自実装）: 旧亜種名など、属名と識別語が離れて出現するケースを共起判定によって拾い上げる。  
・ステップ3: CITESの法制度（属内の全種に法的効力が及ぶ）を反映した「属単位」での一括マッチングする。  
・ステップ4: 編集距離を用いたファジーマッチ（タイプミスの救済）を行う。
（ただし、不確実な情報による断定リスクを避けるため、検索画面には表示せず管理者用のログにのみ出力する設計としています。）

対象サイトの特性に合わせた柔軟なアーキテクチャ対象サイトの技術方式（ShopifyのJSON API、静的HTML、PDF、Excel）ごとに適切なパーサーを使い分け、
共通処理をモジュール化してオーケストレーターから呼び出す拡張性の高い設計を採用しています。

また、PDFやExcelのカタログを配布するサイトでは、ファイルのURLを直接指定するのではなく、
HTMLから最新ファイルのリンクを自動検出する仕組みを構築し、バージョンや季節によるファイル変更に耐えうる保守性を確保しました。

倫理的かつサーバー負荷に配慮したスクレイピング設計技術的な可否だけでなく、対象サイトの意思表示とサーバーへの影響を最優先に設計しています。
robots.txtを厳守し、アクセス禁止パス（/backend/など）やボット拒否の明記がある場合は、
APIが利用可能であっても意図的にスクレイピング対象から除外する判断を行いました。

150以上の属を扱う大規模サイトでは、全ページを闇雲にクロールするのではなく、
マスターデータベースに登録済みの保護対象属にのみ絞り込んでアクセスすることで、相手サーバーへのリクエスト数を削減しています。

実データ駆動のテスト駆動開発（TDD）モックデータではなく、実際のCITES/IUCNデータベースを用いた自動テストを構築しています。
運用中に発見された「種小名直後のカンマによる判定スキップ」などの実データ特有のバグに対しても、
即座にロジックを修正して回帰テストを追加し、システムの堅牢性を継続的に向上させています
